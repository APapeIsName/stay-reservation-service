# 면접 관점 산출물

## Rule
모든 의사결정·구현은 **이력서·면접에서 설명 가능한 형태**로 남긴다. 의도·대안·트레이드오프를 함께 명시.

## Why
이번 부트캠프 진행 목적이 "이력서·면접 즉, 더욱 실무적이고 효율적인 입장" (사용자 방침). 학습용 천천히가 아니라 **면접 자산 중심**.

## How to apply
- 요구사항·계획 문서에 **D-N (결정 번호)** + 채택 이유·대안·트레이드오프를 기록 (예: `docs/round-1/01-signup-requirements.md` D-1\~D-8)
- 코드 리뷰 시 "왜 이 구조인가" 답할 수 있도록 주석/문서/PR 본문 정리
- 각 라운드 작업 문서 하단에 **"면접 포인트 메모"** 별도 섹션 (`docs/round-1/02-tdd-plan.md` Part D 참조)
- 군더더기·실험성 코드 자제. 결과물의 **설명 가능성**을 우선
- **위반 신호**: "그냥 이렇게 했다" 식 결정 / 트레이드오프 누락 / 대안 검토 흔적 없음
